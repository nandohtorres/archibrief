How a review is built

Three layers, each checking the one before it.

01

Deterministic checks

16 rule checks run over the parsed Terraform: public-access blocks, wildcard IAM, unencrypted storage, single-AZ databases, missing log validation, and more. Same input, same result.

02

Retrieved guidance

Relevant passages are pulled from the AWS Well-Architected Framework and AWS security best-practice documentation, so the review argues from the source, not from memory.

03

Grounded review

A language model weighs findings against your brief. Every citation it emits is re-checked against the retrieved passages before the report is published.

What it can and can't tell you

A review is only as good as what it can see. ArchiBrief is explicit about that boundary.

  • It never touches your AWS account.No credentials, no API calls into your environment. It reads only the Terraform and brief you submit.
  • Every finding cites its evidence.The file and lines it's about, plus the AWS passage it relies on. You can check each one yourself.
  • Gaps are labeled, not guessed.If a control could live outside the submitted code, such as an organization-wide CloudTrail, the finding says so and is marked "not observable".
  • It is not a compliance certification.It's a second opinion to inform a decision, not an audit or a guarantee of safety.
