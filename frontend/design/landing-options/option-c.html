How it works

The same three steps run for every review, including the samples below.

  1. You submit Terraform and a brief

    A Terraform archive plus a few sentences about the workload: traffic, availability target, data rules.

    The brief matters. "99.95% availability" turns a single-AZ database from a footnote into a finding.

    streaming-platform.tarinput
    • main.tf
    • modules/
    • cdn/cloudfront.tf
    • origin/s3.tf
    • transcode/iam.tf
    • history/dynamodb.tf

    Workload briefVideo streaming for subscribers in North America and the EU. Target 99.95% availability. Viewing history is personal data.

  2. Rules run, guidance is retrieved

    16 deterministic checks scan the parsed Terraform. Relevant passages are then pulled from AWS Well-Architected and security best-practice docs.

    Anything outside the submitted code is marked as a gap, never assumed.

    rule checksdeterministic
    • FAILIAM policy 'transcode_worker' grants wildcard Action "*"
    • FAILS3 bucket 'media_origin' has no public-access block
    • PASSDynamoDB 'watch_history' has point-in-time recovery
    • GAPNo CloudTrail in submission; may exist at org level

    Retrieved: SEC03-BP02 · SEC08-BP02 · REL10-BP01

  3. You get a cited report

    A grounded model weighs each result against your brief. Its citations are re-checked against the retrieved passages before anything is published.

    Each finding: the code it's about, the guidance it relies on, a confidence score, and a recommended fix.

What it checks

  • Public exposureS3 public access, open security groups
  • Identity & accesswildcard IAM, unconditioned trust
  • Encryption at restS3, EBS, RDS storage
  • Recoverabilityversioning, point-in-time recovery
  • Availabilitysingle-AZ databases vs. your target
  • Audit trailCloudTrail and log validation

What ArchiBrief won't claim

It never touches your AWS account. It reads only the files you submit. No credentials, no API calls into your environment.

It can't see what you didn't submit. Org-level controls and unsubmitted modules show up as gaps, not passes or failures.

It's not a compliance audit. It's a cited second opinion to help you decide what to fix first.
